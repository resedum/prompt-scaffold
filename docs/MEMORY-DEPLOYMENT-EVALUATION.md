# 记忆工具 · 「独立成应用」vs「并入 Prompt Scaffold」评估

> 产品经理：许清楚 ｜ 日期：2026-11-08
> 结论先行，六维度逐项权衡，最后给落地建议。

---

## 一、结论先行

**推荐：产品层独立、技术层合并 —— 一个代码库，但把「记忆」做成可独立启动、独立窗口、独立托盘的形态，未来可独立打包分发。**

- **不推荐「完全独立的产品 / 独立代码库」**：当下个人版开发资源有限，重搭 Electron 全套基建成本翻倍、价值减半。
- **也不推荐「只是 Prompt Scaffold 主窗口里的一个 Tab」**：记事本的用户面与心智都不该被锁死在「提示词工具」里。
- **折中最优**：复用一套代码与基建，但给「记忆」独立的窗口、独立的托盘入口、独立的全局快捷键与命令行启动；产品命名与对外呈现按「独立记事本」来做；条件成熟时再编译出独立分发包。

## 二、六维度逐项对比

### 维度 1：用户体验

| | 独立应用 | 并入（Tab） |
|---|---|---|
| 随手记门槛 | 托盘 / 快捷键秒开、秒记 | 需先开 Scaffold 主窗口再切 Tab，多一步 |
| 场景匹配 | 记事本 = 高频低负荷，独立更顺 | 提示词工具 = 低频高负荷，心智有摩擦 |

**分析**：「随手记」的核心是「秒开、秒记、不打扰」。纯 Tab 形态门槛偏高；但若并入时做「独立启动形态」（独立窗口 + 托盘 + 快捷键），体验可与独立应用拉平。→ **支持「合并 + 独立启动形态」**。

### 维度 2：开发成本

| | 独立应用 | 并入 |
|---|---|---|
| 复用 | 窗口 / 托盘 / 存储 / llm / i18n / 打包 / 测试要重搭 | 100% 复用现有基建 |
| 新增 | 全套壳 + 数据层 + 面板 | 仅数据模型 + 存储层 + 面板 |

**分析**：独立成独立代码库要重搭 Electron 壳、托盘、`store.ts` 原子写、`llm.ts`、i18n、导入导出、测试框架，成本翻倍；并入几乎零基建成本。→ **明显支持「合并」**。

### 维度 3：维护成本

| | 独立应用 | 并入 |
|---|---|---|
| 代码 / 打包 | 两套代码、两套打包、双份依赖升级 | 一套代码 + feature flag |
| 稳定性 | 互不影响 | 记忆模块 bug 可能波及主应用，反之亦然 |

**分析**：长期看两套代码维护成本高；合并一套代码最省，但需靠 feature flag 单一裁决点隔离。→ **支持「合并」，但要求清晰模块边界**。

### 维度 4：市场 / 分发

| | 独立应用 | 并入 |
|---|---|---|
| 用户面 | 记事本 = 大众品类，可独立命名 / 获客 / 定价 | 锁定在「提示词优化者」细分受众 |
| 分发 | 独立 App 好推广 | 作为功能增强现有产品，搭便车 |

**分析**：这是**独立的唯一强理由**。记事本用户面（任何想记东西的人）远大于 Prompt Scaffold 用户面（优化提示词的人）。若目标是做通用记事本产品、要独立获客，则必须独立；若目标只是服务现有用户，则并入更省。→ **取决于产品战略，见结论**。

### 维度 5：技术耦合

强耦合点只有三处：

1. **维度清单增强输入**：NoteEditor 的「补全维度」复用 `generateDimensions` + `DimensionList`。
2. **记忆提升为维度习惯**：条目写入 `dimensionHabits`。
3. **需求底稿归档为记忆**：底稿确认后归档为记忆条目。

**独立后怎么解耦**：把这三处抽象成可插拔适配器（如 `EnhanceProvider` / `HabitSink`），独立版「不装 Scaffold 就没有维度增强」，或通过 MCP / 文件互通。

**分析**：这三处是真实增值，但只服务「提示词工作流」这个细分场景，**不是记事本的核心价值**（记、找、版本、备份）。独立后这条线会变弱，但可接受；若合并则保留这条增值。→ **中性偏「合并保增值」，但非决定性**。

### 维度 6：用户心智

| | 独立应用 | 并入 |
|---|---|---|
| 心智 | 「一个工具干一件事」，记事本就是记事本 | 「一个工具箱」，一应用多身份 |
| 匹配 | 契合「极简随手记」预期 | 心智变重 |

**分析**：记事本是高频低认知负荷行为，塞进低频高认知负荷的提示词工具里，心智不匹配。独立命名 + 独立入口可避免此问题。→ **支持「产品层独立呈现」**。

## 三、最终推荐

**一句话：短期「合并交付 + 独立启动形态」，中长期「可独立打包分发」。**

具体落地：

1. **一个代码库**：记忆模块与 Prompt Scaffold 同仓、复用基建（窗口 / 托盘 / 存储 / llm / i18n / 测试），用 feature flag 隔离，个人版不加载企业后端路径。
2. **独立启动形态（产品层独立）**：
   - 独立窗口实例（不依附 Scaffold 主窗口）；
   - 独立托盘图标 / 右键菜单（「新建记事」「打开记事本」）；
   - 全局快捷键（如 `Ctrl+Shift+M`）直接弹出记事编辑；
   - 命令行 `scaffold --memory` 直接打开记忆面板。
3. **独立命名与呈现**：对用户叫「记忆工具」，不叫「Prompt Scaffold 的记忆 Tab」。
4. **未来拆包**：当记事本被验证有独立市场时，抽出共享包、编译出仅含记忆模块的独立分发包（`EDITION=memory` 裁剪）。

**判定标准（给主理人转达）**：

- 如果目标是「**通用记事本产品、要独立获客 / 定价**」→ 逐步走向完全独立，先按上面折中落地，再拆包。
- 如果目标是「**给 Prompt Scaffold 现有用户加一个记事本**」→ 维持「合并 + 独立启动形态」，永不拆包。
