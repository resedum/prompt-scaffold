## 3. 核心机制：它到底怎么"提高指令精度"

它的本质是**"改写 + 迭代评测"的提示词工作台**，不是一次性套模板改写。完整工作流如下：

```
① 获取提示词 ──► ② 智能优化（LLM 改写，可多轮迭代）──► ③ 测试与评估 ──► ④ 保存为可复用资产
  (手写/模板/           (系统提示词 与 用户提示词         (分析 / 单结果评估 /       (版本历史 +
   本地文件/           双模式分别优化)                   多结果对比评估)           可复现示例 + 来源绑定)
   Prompt Garden)
```

**关键技术点**：

1. **双模式优化**：区分「系统提示词优化（system prompt）」和「用户提示词优化（user prompt）」两种模式——前者是优化智能体/机器人的"人设与规则"，后者是优化你实际输入的那句话。
2. **评估驱动的智能重写（Evaluation-driven Smart Rewrite）**：这是它最值得学的地方。不是"改写完就交给你"，而是闭环：
   > **优化 → 评估 → 不达标则再次优化 → 达标则保存**
   先跑一版输出，用一个「评估器」判断好坏，不好就基于评估结果再改，直到达标。核心思想是**用模型的实际输出做反馈信号来打磨提示词**，而不是靠人凭感觉改。
3. **评测三件套**：分析（Analysis）/ 单结果评估 / **多结果对比评估**——把"原始提示词"和"优化后提示词"喂给同一个模型，并排对比输出，用证据判断"改写是否真的变好了"（而不是"更长=更好"）。
4. **多轮迭代**：MCP 暴露 `iterate-prompt` 工具，支持多轮改进而非单次改写。
5. **版本化资产管理**：优化出好版本后可存为「收藏」，带**版本历史、可复现示例、来源绑定**，支持回滚；还有公共 `Prompt Garden` 提示词库可检索/导入。
6. **纯客户端 + 自带 key**：所有数据留在浏览器/本地，模型请求直连你配置的服务商（OpenAI / Gemini / DeepSeek / Grok / 智谱 / 硅基流动 / MiniMax / 任意 OpenAI 兼容端点 / 本地 Ollama），**不经中间服务器**——隐私立场与我们一致。
7. **多模型归一化 + 图像生成**：文本优化之外还支持文生图/图生图提示词优化；通过"OpenAI 兼容端点"把各家差异归一化。
8. **MCP 集成**：Docker 形态内置 MCP Server（`/mcp`），暴露 `optimize-user-prompt`、`optimize-system-prompt`、`iterate-prompt` 三个工具，可被 Claude Desktop 等直接调用。

## 4. 与我们 Prompt Scaffold 的异同

### 4.1 相同点（立场重叠）

| 维度 | 两者共识 |
|---|---|
| 赛道 | 都在"提示词工程外围工具"这条线 |
| 用户主导 | 它"改写+评测后你拍板保存"，我们"AI 只提议、用户采纳才写入"——都拒绝替用户暗箱决定 |
| 隐私/本地 | 都本地优先、纯客户端、用用户自备的模型 key、数据直连服务商 |
| MCP 野心 | 它已做 MCP Server；我们 PRD 规划了 MCP Server 作为广度补充 |
| 多模型 | 都走"多模型预设 + OpenAI 兼容归一化 + 本地 Ollama" |

### 4.2 本质不同（这是关键）

| 维度 | prompt-optimizer | Prompt Scaffold（我们） |
|---|---|---|
| **核心动作** | **替用户改写**提示词（产出"优化后的提示词"） | **绝不替用户改写**，产出"可勾选、可修改的维度清单原材料" |
| **解决什么问题** | 话"说得不够好" → 把话说好 | 话"一时想不到该说什么" → 帮用户想全，长对话里守住要求 |
| **优化对象** | 提示词**文本本身**（input → better input） | 用户的**需求思考过程**（input → 结构化维度 + 措辞建议 + 长期底稿） |
| **评测方式** | 内置自动评测（新旧提示词并排跑模型对比） | 目前是"对照真实长周期任务"（PRD §十一），尚无内置自动化评测 |
| **产物形态** | 一条更完整、更适合执行的提示词 | "用户原话 + 追加的补充说明"，原话不被覆盖 |

### 4.3 关系结论

**不是竞品，是互补 + 可借鉴。** 我们在"想全 + 守住 + 记忆"上更强，它在"改写 + 评测 + 版本化"上更强。二者处理的是提示词生命周期里**前后相邻的两个环节**：先在我们这里"想全"（勾维度、存底稿），再（可选）交给类似它的能力"打磨"。

> 可能的融合方向（长期，非本阶段）：用户在我们这里勾选完维度、生成补充说明后，可**可选地**调用"改写/评测"能力做进一步打磨——但必须守住我们的铁律：**用户原话不被覆盖，改写只能以"追加建议"形式呈现**。这是与它最根本的差异，不能丢。

## 5. 另两个近似项目（补充方法论）

1. **`devilking7x/prompt-optimizer`**（local-first 启发式评分器）：**无需 LLM、无需 API key**，用 8 条本地规则给提示词打 0–100 分（缺角色 / 缺输出格式 / 模糊词 / 缺约束 / 超长等），逐条解释问题并给出修复建议，100% 本地运行。→ **与我们的"规则 + 硬编码维度池兜底，不接模型也能跑"高度同源**，是"本地自检评分"的直接参考。
2. **`ademakdogan/prompt-optimizer`**（mentor-agent 进化）：从**标注样本**出发，导师智能体迭代"生成 → 评测器判对错 → 导师模型分析失败样例给改进建议 → 下一轮"，准确率打平时选更短（省 token）的提示词。→ 面向"结构化抽取任务"的自动提示词进化，方法更重，但"评测器 + 失败样例驱动"的思想可借鉴。

## 6. 可借鉴点清单（5 条，可落地）

> 都遵循一个前提：**借鉴其"评测/版本化/资产化"的思想，不引入其"替用户改写"的动作**。

1. **本地启发式"自检评分器"（零 LLM 成本，最高优先级）**
   给我们的「维度清单 / 需求底稿」加一个**纯规则的本地自检**，对标 `devilking7x` 的 8 条启发式 + `linshenkx` 的"评估驱动"思想。例如对生成的底稿提示："⚠ 缺输出格式 / ⚠ 存在模糊词（'好一点''差不多'）/ ⚠ 未声明硬约束"。**只提示、不替用户改**，完全复用我们"规则 + 硬编码维度池兜底、不接模型也能跑"的既定路线，成本近乎为零。

2. **版本化资产 + 来源标记（与任务二"版本控制"直接呼应）**
   我们的"已采纳维度措辞习惯 / 需求底稿"应像它一样带**版本历史、来源标记、可回滚**。`MemoryHabit` 已有 `source/createdAt/updatedAt`，可再加 `version/replacedBy` 字段；底稿每次确认产生一个快照版本，误删可回退——这正是任务二"版本控制"的最小实现。

3. **公共提示词仓库（Prompt Garden）的"元数据 + 来源绑定"设计**
   PRD 已规划"公共知识库（只读）"。可参考它 garden 的资产组织方式：每条提示词带 `category / output-format / status / source` 元数据 + 来源标记。我们只**检索、拆解、映射**（拆成"维度词 + 具体表述"），**不向公共库写入**——PRD 已定，方向与其一致，可借鉴其索引粒度。

4. **MCP 工具化暴露，粒度对齐**
   它把能力暴露为 `optimize-user-prompt / optimize-system-prompt / iterate-prompt` 三个细粒度工具。我们规划中的 MCP Server 可对齐此粒度，暴露 `generate-dimensions / summarize-conversation / maintain-draft` 等，让外部 Agent 在"按下发送键前"直接调用——与 PRD"钩子 + MCP"路线吻合。

5. **多模型 OpenAI 兼容归一化 + 本地 Ollama**
   它的"任意 OpenAI 兼容端点 + 本地 Ollama 一键接入"做法，印证了我们 PRD 里"provider 归一化兜底厂商差异"的方向正确；可复用其"自定义端点"配置形态，让智谱 / DeepSeek / Ollama 统一走一套 `base_url / api_key / model` 三字段。

## 7. 边界提醒（给团队的诚实提示）

- **许可证不清**：GitHub 标记 `Other`，README 说 AGPL-3.0。若未来直接复用其代码/自托管其界面，须先核实协议；**我们的策略是"借鉴思想，不复制代码"**，风险可控。
- **别学它的"替用户改写"**：那是它产品里最核心也最容易被我们误抄的部分。我们的差异化恰恰是"不替用户改写、只产出原材料"，一旦开始改写，就丢了定位。
- **它的评测依赖反复调模型**：每次评测都烧 token（调用用户自己的模型跑新旧对比）。我们做"本地启发式自检"就能拿到 80% 收益，**不必为此引入高成本的自动化跑模型评测**。
